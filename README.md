# 門診 ePRO — 回診前症狀紀錄

免疫治療（IO）與抗體藥物複合體（ADC）門診的**到診前輔助工具**。

| 頁面 | 網址 | 說明 |
|---|---|---|
| 病人端 | [/](https://jnynlin.github.io/clinic-epro/) | 候診時用手機填，填完產生「看診用摘要」拿給醫師看 |
| 醫師端 | [/doctor.html](https://jnynlin.github.io/clinic-epro/doctor.html) | 介面示範，八位虛構病人 |

**兩頁都沒有後端。** 病人端的資料完全不離開病人手機；醫師端是靜態示範，
資料事先算好烤進頁面，按「確認並記錄」不會儲存。

## 定位

**到診前輔助工具，不是監測系統。** 資料單向流動：病人 → 診間，在看診當下被消費，
不產生任何回覆通道。沒有人力回應的警示只會製造雜訊，而雜訊會讓真正重要的訊號一起被忽略。

因此病人端**不顯示由系統判定的緊急度**，只給一句固定的、人人都看到的安全網提醒。

## 不是什麼

* **不產生 CTCAE 分級。** 題目設計對應 CTCAE v6.0 分級條件所需的證據，
  但選詞與定級是臨床推論，屬醫師職權。醫師端輸出的是「證據信封」——
  病人證據已確立的下限、仍可能的上限、以及還缺什麼才能收斂 —— 不是一個分數。
* **有些詞條問卷定不了級。** Pneumonitis、Colitis、Myocarditis 的第一級在定義上
  就是無症狀，病人全部否認也不能排除，頁面會明講。
* **繁體中文題目為自譯**，非 NCI 語言學驗證版本，僅作臨床溝通輔助。
* 紅旗規則為本院自訂，不是 CTCAE 或 PRO-CTCAE 的一部分。

## 設計要點

* **面板依藥物類別（IO / ADC）而非疾病** —— 毒性是藥的性質不是腫瘤的性質。
* **開放主訴問在結構題之前** —— 先跑清單會定錨，病人後面只會補充清單提過的。
* **日常活動兩題照 CTCAE 官方定義措辭**（工具性 vs 自我照顧）——
  v6.0 幾乎每個症狀詞條的二三級分界就是這兩件事。
* **醫師端清單即決策介面** —— 一診四五十人時，瓶頸不是讀快一點，
  是多數病人根本不需要被讀。清單預設只顯示需要處理的。

## 資料來源

CTCAE v6.0（2025 發布，2026-01-20 勘誤），NCI/CTEP。
